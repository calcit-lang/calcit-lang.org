Calcit · typed functional language

为 AI Agent
准备的命令行与类型系统

结构化源码 · 可查询的 CLI · 严格类型诊断

Agent 改代码, 常见的三种失误

  • 凭记忆猜文件和缩进, 改错位置
  • 大段文本重写, 一次破坏多处
  • 类型信息缺失, 错误到运行时才暴露

Calcit 的回答: 让语言和工具链自己提供证据。

源码是一棵可查询的语法树

calcit.cirru

Cirru EDN 快照保存程序树, 不是按行维护的文本, 也不允许文本 patch。

Cirru 语法

缩进表达结构, 人读起来像普通代码, 机器读到的是精确的节点。

三层分开

源 AST、宏展开后的 core、生成的 JavaScript; 只有源树可写。

查询 → 修改 → 验证


  

  
  

    
每一步都有护栏

    

      
先读契约
紧凑的修改契约与稳定摘要, 摘要不变就不必重读全文。

      
定位真实路径
query / search / tree show 给出 namespace、definition 与 AST 路径。

      
串行与 revision
transaction 与 --expect-revision 防止并行写入互相覆盖。

    

  

  
  

    
类型是 Agent 的护栏

    

  

  
  

    
严格, 但不假装知道一切

    

      
已知矛盾 → 编译期报错
带源码位置与类型证据, 不会拖到运行时。

      
开放数据 → 边界 decode
Dynamic 只用于 JS FFI 与外部输入, 解码成 Result 后再使用。

      
迁移 → 可审阅的 fix
calcit fix 给出确定性改写建议, 不用 unsafe-coerce 糊弄。

    

  

  
  

    
文档也在命令行里

    
$ calcit docs search 'typed dispatch' --module respo.calcit
$ calcit docs check-md content/intro.md --failures-only

    
示例代码会被执行检查, 减少过期文档对 Agent 的误导。
