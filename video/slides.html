时间线 · 里程碑

从 0.13 到 0.28 的几个节点

8 月 6 日0.13.0此后一个月内，0.13 系列发布了约八十个补丁版本。
9 月 7 日0.14.0运行、检查与代码生成默认严格诊断。
9 月 15 日前后0.14.20 – 0.15calcit wasm / wasi 成为公开命令；组件边界覆盖 Struct、Enum、数值，随后是 async。
9 月 19 – 28 日0.17 – 0.26近乎每天一版：caps 拆分、模块仓库、严格检查继续收紧。
9 月 29 日 – 10 月 2 日0.27 – 0.28项目级结构化改写，受检的 JS 宿主转换。
时间线 · 试验与取舍

方向包含很多试验：保留、拆出、放下

留

保留并深化

  • 命令行优先的结构化编辑
  • 默认严格的类型检查
  • 新增编译投入集中在 WebAssembly
拆

拆出去独立演进

  • caps 包管理，独立发布
  • calcit-native-ffi 共享 ABI
  • calcit-bindgen，实验性生成器
放

放下或不再推荐

  • Calcit Editor 不再是日常路径
  • 近期没有 LSP 计划
  • compact.cirru 退役，统一 calcit.cirru

试验的结果，最终都落在命令行和类型系统这两条主线上。

主线一 · 命令行

一套命令，覆盖“看、改、验”

看

query

ns、defs、search、type、usages，读到的都是真实的定义与路径。

改

edit · tree

按 AST 路径替换、插入、包裹；cursor 负责连续操作。

验

--check-only · test

默认严格检查；定义可以挂测试，空选择不算通过。

迁

fix · analyze

确定性的迁移建议，和 weak-types、check-public 等分析。

$ calcit query defs app.schema
$ calcit tree show app.schema/store --path ''
$ calcit tree replace app.schema/store --path '<path>' --input-format cirru --code 'quote <node>'
$ calcit --check-only
主线二 · 类型系统

类型从“提示”变成“证据”

名义数据

Struct 与 Enum 表达领域模型，match 做穷尽检查，Option 表示缺失，Result 表示失败。

schema 与泛型

函数签名写在 schema 里，泛型和 trait 约束让回调、容器的类型关系可以被传递。

Dynamic 是边界

只在 JS FFI 和外部数据处使用；用解码器验证后再进入业务，而不是强制转换。

诊断带证据

错误码、期望与实际类型、AST 路径都在输出里，Agent 可以按证据修复。

主线三 · 工程与目标平台

工具链拆分，目标平台明确

caps 独立

依赖由 deps.cirru 声明，caps --ci 安装，项目读取本地模块链接。

WASM · WASI

calcit wasm、calcit wasi 成为公开命令，Component 边界覆盖 Struct、Enum、明确宽度数值与 async。

受检的 JS 边界

JS FFI 带 :js-ffi feature 与类型契约，宿主转换需要显式、可审阅。

接下来挑几个具体案例，稍微展开讲讲背后的设计意图。

案例 1默认严格诊断

错误要尽早、带着证据出现

defn add-one (n) (+ n 1)
; schema: Fn (Number) -> Number

defn main! ()
  println $ add-one |hello
$ calcit --check-only
[W_FN_ARG_TYPE_MISMATCH]
Function `app.main/add-one`
arg 1 expects `:number`, got `:string`
@app.main/main! @3.1
  • 默认严格：0.14 起不必再开开关；旧项目用 --compat-types 暂时过渡。
  • 不放宽：升级时不扩大 Dynamic，不用 unsafe-coerce 通过检查。
案例 2结构化编辑的安全

多个 Agent 同时改，也不互相覆盖

Snapshot 不是文本

calcit.cirru 是 Cirru EDN 树，禁止文本 patch，只用 edit、tree、cursor。

先展示，再修改

target 与 path 必须来自 query 和 tree show，改完再回读。

并发保护

写入前核对 revision，多步变更放进事务，先 dry-run。

$ calcit edit transaction \
    --expect-revision md5:949975ca… \
    --dry-run --code '<ops>'

# revision 变了就拒绝写入
# 版本也要对得上：
#   deps.cirru :calcit-version
案例 3方法契约：proven 与 open

知道哪些调用“被证明”，哪些还“开放”

$ calcit query type ":: 'List 'Number"
.filter  proven  (fn(number) -> bool) -> list<number>
.find    proven  (fn(number) -> bool) -> Option<number>
.append  proven  (number) -> list<number>
.each    open    specialized contract retains Dynamic
  • proven：接收者与签名有静态证据，可以放心调用。
  • open：仍含 Dynamic，需要检查调用边界，不等于安全。

Agent 不必凭名字猜 API，先查类型，再决定怎么写。

案例 4外部数据的类型边界

解析成功，不等于类型验证成功

; 只证明“语法合法”，内容仍然开放
"..." .parse-cirru-edn
  -> Result<Dynamic, String>

; 在输入边界用解码器真正检查形状
try-parse-cirru-edn-as text
  :: 'List $ :: 'List 'Number
  -> Result<List<List<Number>>, String>

失败必须处理

返回 Result，不自动插入 unwrap、默认值或 unsafe cast。

JS FFI 同理

声明类型不能证明 JS 实现正确，宿主边界需要独立验证。

案例 5给 Agent 的文档与契约

把“每次都要读的规则”做小、做稳

$ calcit docs agents --contract
Agent mutation contract: v1
Agent contract digest: md5:8c8ec6f2…
Agent contract length: 2969 bytes, 40 lines

$ calcit docs search 'typed dispatch' --module respo.calcit
Typed dispatch with type slots [module:respo.calcit]
  • 紧凑契约：修改前只读几十行，摘要不变就不必重读全文。
  • 文档可查询：语言与模块文档都能从命令行搜索，减少搬运过期内容。
  • 输出可机读：--format edn 保留 Tag 与 Symbol 语义，供自动分支。
案例 6确定性的迁移修复

升级交给规则，不交给猜测

$ calcit fix --preset surface-latest-v2
mode: preview   suggestions: 0   changed: false
rules: removed-data-api-v1, named-enum-constructor-v1,
       named-struct-constructor-v1, redundant-do-v1,
       single-expression-do-v1

先预览

默认只给建议，--apply 才原子写入。

可审阅

每条规则有稳定 ID，可以限定 namespace 或 definition。

有边界

不猜类型、不填默认值、不用 unsafe-coerce 代替判断。

怎么跟上

已有项目的升级路径

01

固定版本

以 deps.cirru 的 calcit-version 为准，CLI 要对得上。

02

读契约

docs agents --contract，再按需读 --full。

03

检查并修复

--check-only 看诊断，fix 预览迁移，再逐项验证。

$ caps --ci
$ calcit --check-only
$ calcit fix --preset surface-latest-v2
$ calcit docs agents --contract
$ calcit test <ns/def> --require-match
$ calcit js
