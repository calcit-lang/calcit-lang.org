# Upgrade calcit-lang.org to Calcit 0.13.77

- Raise the compiler baseline from 0.13.68 to 0.13.77 and pin the JavaScript runtime package to the exact matching version.
- Pin setup-calcit 1.3.0 to its immutable commit and verify the exact linked toolchain after strict module and immutable JavaScript dependency installation.
- Restrict the workflow token to read-only repository contents while preserving the existing check-only, no-growth static quality, JS/Vite, and push-only deployment gates.
- Preserve site content and behavior, package version 0.0.2, and the reviewed static quality baseline.
- Align the direct Respo family dependencies with their latest published compatible graph: Respo 0.16.90, Reel 0.6.12, Respo UI 0.7.15, and Respo Markdown 0.4.30.
- Correct two project-local 0.13.77 contracts through the Calcit CLI: `add-link` returns `respo.schema/Element`, and `dispatch!` compares the Enum head as `Option<Tag>`.

## Blocked validation

- Strict Caps, immutable Yarn, exact Calcit/procs 0.13.77 toolchain verification, canonical formatting, and all six published module links pass.
- Published Respo 0.16.90 leaves exactly one check-only warning at `respo.core/decorate-defcomp`; this is the merged but unreleased fix tracked by calcit #670.
- A temporary source-link to the clean Respo post-fix worktree proves both entries pass check-only, the checked-in no-growth baseline passes (`typeNone` 14, `typeNotFull` 8, `schemaDynamic` 31, `codeDynamic` 0, `codeNil` 11, `declaredOptional` 0, `deprecatedCalls` 0), JS generation passes, and the Node 24.4.1/Vite 8.2.1 production build succeeds.
- The project-local module link was restored to immutable published Respo 0.16.90 after that diagnostic. No pull request should be opened before a release containing the Respo fix is consumable and the same full workflow passes without a source link.
